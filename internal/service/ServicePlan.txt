Универсальный план по созданию любого сервиса :

1. Определить Границы и Контракт (Что сервис ДЕЛАЕТ?) : 	1)Создаю type MyService interface и выписываю методы.

								2)Создаю DTO-структуры для входящих параметров каждого метода
								
								
2. Определи Внешние Зависимости (Что сервису НУЖНО для работы?) : 	1)Пишу интерфейсы всех зависимостей прямо в файле сервиса. (Repository , Notifier , PaymentGateway)

									2)Создаю приватную структуру сервиса type myService struct, куда кладу эти интерфейсы в качестве полей.
									
									
3. Напиши «Каркас» (Constructor + Boilerplate) : 			1)Пишешь функцию NewMyService(...).

									2)В аргументы передаешь интерфейсы из Шага 2.
									

4. Реализуй Бизнес-Логику по Шаблону 4V : 	1)Validation (Валидация): Проверь входящий DTO. Права доступа, лимиты, некорректные ID.

						2)Verification (Проверка состояния): Сделай запрос через зависимость (например, repo.GetByID), чтобы проверить, существует ли сущность, активна ли она и т.д.

						3)Variation (Изменение состояния / Сборка модели): Примени бизнес-правила (считай цены, меняй статусы, генерируй токены, собирай модель models.Entity).

						4)Volume Persistence (Сохранение и Побочные эффекты): Вызови методы сохранения (repo.Save) или отправки уведомлений (notifier.Send).
